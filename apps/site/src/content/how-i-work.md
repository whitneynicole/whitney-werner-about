---
heading: How I work with agents
---

1. **Context before code.** At a new team, I write down how the work really happens before I touch anything. In a repo, that becomes the project context agents read first.
2. **Specs, then tickets.** Every agent task gets a written spec with "done when" criteria. Vague tickets make agents guess.
3. **No agent approves its own work.** Independent reviewers, verification before anything is accepted, and CI that has to pass.
4. **Fail closed.** If a run is incomplete or a check fails, the last good state stays live, and a person hears about it.
5. **Teach it, then leave it running.** I document what I build and train the people who use it, so it keeps working after I step away.
